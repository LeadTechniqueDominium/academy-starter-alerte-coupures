# AC-04 · « Moi aussi » et coupures confirmées

## Contexte

Un signalement isolé peut être une erreur ou une plaisanterie. Pour fiabiliser l'information, les habitants
qui subissent la même coupure cliquent sur « Moi aussi ». Une coupure devient « confirmée » dès qu'elle
réunit des signalements de 3 téléphones différents.

## Critères d'acceptation

- [ ] Sur la liste publique, chaque coupure en cours propose « Moi aussi » : la personne indique son téléphone et un signalement « Moi aussi » est ajouté à cette coupure.
- [ ] Un même téléphone ne compte qu'une fois par coupure : un second « Moi aussi » est refusé avec un message clair.
- [ ] Une coupure devient « confirmée » (date enregistrée dans `confirmed_at`) dès qu'elle réunit des signalements de 3 téléphones différents ; deux signalements du même téléphone ne comptent que pour un.
- [ ] Un badge « Confirmée » apparaît sur la liste publique et dans l'espace de modération.
- [ ] Impossible de voter « Moi aussi » pour une coupure résolue.
- [ ] La règle de confirmation est dans une classe dédiée (par exemple `App\Actions\ConfirmIncidentIfNeeded`) testée unitairement.

## Indices

- Nouvelle migration : `confirmed_at` (timestamp, nullable) sur `incidents`.
- Téléphones différents : `$incident->reports()->distinct()->count('phone')`.
- Route : `Route::post('/coupures/{incident}/moi-aussi', ...)` avec une Form Request qui valide le téléphone (même règle que `StoreReportRequest`).
- Alpine.js peut afficher le petit formulaire au clic : `x-data="{ open: false }"`, `@click="open = true"`, `x-show="open"`.
