# AC-01 · Filtres et signalements actifs par quartier

| Difficulté | Branche | Tests à compléter |
| --- | --- | --- |
| facile | `ticket/AC-01` | `tests/Feature/Tickets/AC-01Test.php` |

## Contexte

La page d'accueil liste tous les signalements des dernières 48 heures, commune par commune. Un habitant de
Yopougon qui cherche les coupures d'électricité doit tout faire défiler. On veut pouvoir filtrer par type
(eau, électricité) et par commune, et voir d'un coup d'œil combien de signalements sont actifs dans chaque
quartier.

## Critères d'acceptation

- [ ] La page d'accueil propose un filtre par type (tous, eau, électricité) et par commune (toutes ou une commune), envoyé en GET (par exemple `/?type=water&commune=6`) ; les choix restent sélectionnés après l'envoi.
- [ ] Le filtre par type n'affiche que les signalements de ce type.
- [ ] Le filtre par commune n'affiche que les signalements de cette commune ; les deux filtres se combinent.
- [ ] Une valeur inconnue (`type=gaz`, `commune=999`) ne provoque jamais d'erreur 500 : elle est ignorée ou signalée par un message clair.
- [ ] Pour chaque quartier affiché, le nombre de signalements actifs (coupure en cours) apparaît, par exemple « Angré · 2 signalements actifs ».

## Indices

- `$request->enum('type', OutageType::class)` renvoie `null` pour une valeur inconnue : pratique pour ignorer un mauvais filtre.
- Construisez la requête pas à pas avec `->when($type, fn ($query) => ...)` et `whereHas('incident', ...)`.
- Les choix du formulaire se conservent avec `request('type')` dans la vue, ou mieux, en passant les valeurs depuis le contrôleur.
- Le compte par quartier peut se calculer sur la collection déjà chargée (`groupBy` puis `count()`), sans requête supplémentaire.
